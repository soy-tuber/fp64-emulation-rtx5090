GeForce RTX 5090 で FP64 エミュレーションを測る

cuBLAS 13 の固定小数点エミュレーション（尾崎スキーム系）を、FP64 を意図的に削られたコンシューマ GPU で実測した記録。測定日 2026-10-04

8.22×最大スループット向上 (n=16384, narrow range)
5.81×wide dynamic range でも
1.719native FP64 の上限 TFLOPS
14.124エミュレーションの TFLOPS
結論を一行で。このカードでは FP64 エミュレーションは native FP64 より速いだけでなく、精度も高い。native は累積丸めで相対誤差 4.0e-15 程度まで劣化するが、エミュレーションは整数で厳密に積和して最後に一度だけ丸めるため、正しく丸めた厳密値に一致する（相対誤差 0 または 1 ULP）。

なぜ測る価値があるのか

GeForce の倍精度は仕様上 FP32 の 1/64 に制限されている。一方で INT8 テンソルコアは3桁 TOPS ある。CUDA 13.0 Update 2 で cuBLAS に入った固定小数点エミュレーションは、FP64 の積を整数の列に分解して INT8 テンソルコアで厳密に計算する——つまり潤沢な資源で枯渇した資源を代替する。

公開されている測定値はデータセンター GPU（native FP64 が速い機種）が中心で、そこでの利得は控えめに見える。しかし FP64 を削られたコンシューマ機では前提が逆であり、倍率が大きくなるはずだ。その実測値がほとんど見当たらないので、自分で測った。

エミュレーション戦略の影響

CUBLAS_EMULATION_STRATEGY は performant（エミュレーションが得と判断したときだけ使う）と eager（積極的に使う）を取る。native がここまで遅いカードでは performant でも常にエミュレーションが選ばれるため、差は出なかった。

ADP は無料ではない。同じ n=8192 で ADP は 13.704 TFLOPS、マンティッサを 48 bit に固定すると 17.793 TFLOPS で 1.30 倍速い。精度はそれぞれ 1.15e-16 と 1.61e-16、どちらも約 1 ULP で実用上同じ（しかも native の 2.29e-15 より一桁良い）。ADP は必要ビット数を決めるために入力を走査するぶんを払っている。入力のレンジが既知なら、固定した方が得だ。

階段状のプラトーが実装を露出させている。要求ビット数を増やしても値が動かない区間が並ぶのは、ビット数が離散的なスライス数に切り上げられているためだ。INT8 のスライスを何枚積むかという内部構造が、外から観測できてしまっている。

native FP64 は電力枠を使い切れない。575 W の枠に対して 221 W しか引かず、SM クロックは 2883 MHz と高いまま張り付く。稼働しているダイ面積が小さすぎて、電力ではなくクロックで律速されているということだ。エミュレーション側は INT8 テンソルコアを動かすため 575 W まで上がり（電力上限に張り付く）、クロックは 2490 MHz に下がる。つまりこの技術は使われずに余っていた電力枠をスループットに変換している。

結果として、FP64 相当の精度を保ったまま電力効率が 4.2 倍になる。消費電力は 2.6 倍に増えるが、仕事量が 10.8 倍になるためだ。

測定方法

  • 計測: cudaEvent による GPU 時間。warmup 2 回ののち 5 回（掃引では 3 回）測り中央値を採用。FLOP は 2n³。
  • 精度の基準: 浮動小数点の参照値ではなく厳密値と比較している。math.fma による two-product で各積の丸め誤差を取り出し、積と誤差の両方を math.fsum で厳密に総和する。これは正しく丸めた内積に一致する。出力行列からランダムに抽出した要素について相対誤差を取った。
  • 入力分布: easy は一様乱数 [-1,1]。hard は正規乱数に 2U(-10,10) を掛けて指数レンジを広げたもの。固定小数点分割の必要ビット数は指数レンジで決まるため、この2本が上下の目安になる。
  • モード切り替え: cuBLAS は環境変数をハンドル生成時に読むため、1モード = 1プロセスで起動している。

この結果が言っていないこと

  • これは DGEMM 単体の測定である。実アプリの利得は FP64 行列積がどれだけ時間を占めるかに支配され、メモリ帯域律速の処理では小さくなる。
  • 機械1台・ドライバ1種・1セッションの測定であり、個体差や温度・電力状態の影響を分離していない。
  • 利得は入力の指数レンジに依存する。極端に広いレンジではさらに下がる。
  • 深層学習の推論には関係がない。推論は FP16/INT8/FP8 で動いており FP64 を使わない。エミュレーションは INT8 の演算量を大量に消費して FP64 の精度を再構成する技術であり、低精度推論を速くするものではない。

再現手順

git clone https://github.com/soy-tuber/fp64-emulation-rtx5090
cd fp64-emulation-rtx5090

# CUDA 13.0u2 以降の cublas64_13.dll / cudart64_13.dll があるディレクトリ
set FP64EMU_CUDA_DIR=C:\path\to\cuda13\dlls

python run_all.py        # 全モードを掃引し results/*.json を作る
python make_report.py    # docs/index.html を生成する

個別に1モードだけ測る場合:

set CUBLAS_EMULATE_DOUBLE_PRECISION=1
python dgemm_bench.py --sizes 16384 --dists easy,hard --label emu
